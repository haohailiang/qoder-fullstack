- 所有对外 API 返回统一包装类型 `com.ecommerce.common.Result<T>`，包含 code/message/data 三字段，成功走 `Result.success()`，失败走 `Result.error(code, message)`。
- 业务异常通过自定义 `BusinessException` 抛出并由 `GlobalExceptionHandler` 统一捕获并转为 `Result.error` 响应。
- 各业务模块遵循 controller → service(impl) → repository(mapper) → entity 的分层结构，Mapper XML 与 Java 接口一一对应置于 `resources/mapper/`。
- 网关侧鉴权后通过 `X-User-Id`、`X-User-Name`、`X-User-Role` 三个请求头（可附 `X-Gateway-Timestamp` / `X-Gateway-Signature`）向下传递用户身份，下游服务从该头读取而非重新解析 JWT；`TrustedAuthenticationFilter` 会把角色转为 `ROLE_{role}` 并默认兜底 `ROLE_USER`。
- 会话失效统一用业务码 `40101`（HTTP 401）表达“已被挤下线/已登出”，前端只在收到 40101 时清理登录态并跳登录页，普通 403 仅提示无权。
- 外部回调不得套用统一 JSON 包装：支付宝异步通知返回纯文本 `success` / `failure`；上传接口要先做前 12 字节魔数与 5MB 大小校验，且图片存储路径必须限定在商品图片目录内。
- 秒杀流程采用 Redis + Lua 预扣库存、RabbitMQ 异步落库的两阶段模式：商品服务用 `SeckillStockService` 原子扣减，订单服务通过 `@RabbitListener` 消费 `SECKILL_QUEUE` 创建订单。
